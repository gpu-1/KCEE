# Local document knowledge

Open **Local documents**, choose a UTF-8 `.txt` or `.md` file, and press **Add document**. Sources are limited to 256 KB, 5000 lines and 1800 characters per line. Binary, non-UTF-8, empty and unsafe filenames are rejected. Sources stay in PostgreSQL on this host; there is no remote extraction, embedding API or model upload. Text PDF import is supported locally; Local English/Spanish OCR is available for scanned pages. Semantic embeddings run locally on Metal.

Documents are immutable original bytes with SHA-256 identity. Identical bytes deduplicate to the first stored name. New content is a separate source version, even if the filename is the same. Line-preserving passages carry original source and passage hashes. Document/chunk tables permit application SELECT and INSERT only; triggers also reject UPDATE, DELETE and TRUNCATE. Archive and restore controls preserve originals and citation history.

**View verified source** checks original bytes against the stored hash in both the local API and browser before showing plain text. Markdown is shown as text, never executed or rendered as active HTML. Original-source download is plain text with `nosniff` and attachment disposition.

Select a verified structural or thermal study and opt in with **Include local document references**. Search uses ranked PostgreSQL English full-text terms, matching any normalized question term, and returns at most four passages. When indexed, results combine semantic similarity and keyword rankings; relevance and claim interpretation require review. Combined context is capped at 20 KB, and full source files are not passed wholesale to the model.

The native model receives study evidence and original excerpts as untrusted data. Document instructions cannot grant tools, change designs, run solvers or approve engineering acceptance. Reference material does not overwrite saved conductivity, allowables or other solver assumptions. Each model-provided document ID must be one of the supplied IDs; unknown IDs and mismatched inline markers are rejected. Inline markers are optional because the structured citation list is displayed below the answer. Exact cited passages, filenames, original line ranges and hashes are shown independently of the generated prose. The original source and all supplied passages are rechecked when retrieving the completed answer.

A valid citation identifies an authentic passage; it does not automatically prove every generated claim follows from that passage or that the document is an authoritative material allowable. Answers remain drafts. JSON exports preserve the question, complete supplied evidence, references, source hashes, model/runtime/prompt fingerprints and settings; TXT exports list the cited filenames and line ranges with source/passage hashes.

For existing databases, apply the repository migration after backing up the database:

```sh
docker exec -i kcee-postgres-1 psql -U kcee -d kcee < infra/postgres/006-local-knowledge.sql
```

Fresh Compose databases apply the numbered initialization scripts automatically. Existing volumes are not reinitialized. Include the PostgreSQL volume in migration/backup planning; document originals are stored in the database, not under `runs/`. Full database backup/restore and destination Mac Studio acceptance remain separate work. The library initially contains the project’s bracket thermal guide uploaded through the website for verification; its stored version remains unchanged if the repository guide later changes.

## Local semantic search

Start Local AI, open Local documents, and press **Index documents** after adding sources. Indexing resumes missing passages in batches of at most 16. Stop Local AI stops both chat and embeddings; keyword retrieval remains available. The website and original documents remain available.

Provision once with `python3 scripts/provision_embeddings.py`. This explicitly downloads the official [Nomic Embed v1.5 GGUF](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5-GGUF) F16 model at revision `0188c9bf409793f810680a5a431e7b899c46104c`, SHA-256 `f7af6f66802f4df86eda10fe9bbcfc75c39562bed48ef6ace719a251cf1c2fdb`. Inference uses the pinned llama.cpp runtime, Metal, mean pooling, 2048-token context, task-specific query/document prefixes, and 768 normalized dimensions. Model weights and private HTTP credentials are not mounted into the API container. A signed local queue carries bounded requests.

Apply `infra/postgres/007-local-embeddings.sql` to existing databases after the original knowledge migration, using the same migration procedure above. Fresh databases initialize both automatically. Derived vectors are append-only and versioned by the full model/runtime manifest; indexing a new model never overwrites source bytes or previous vectors. Each vector has input, source, passage, model and vector hashes. Retrieval verifies these before supplying literal passages to the assistant. JSON answer exports retain retrieval fingerprints and ranking metadata.

Exact pgvector cosine scans suit this initial small library. Candidates below cosine 0.5 are excluded from the semantic ranking; reciprocal rank fusion uses constant 60 and returns at most four passages. These settings were smoke-tested on the project guide, not certified as a relevance benchmark. Missing, stopped or busy embedding services fall back to keywords, recorded in retrieval metadata. Integrity failures reject retrieval. No remote inference or automatic downloads occur during a question.

## PDF import and page citations

Choose a `.pdf` in Local documents and press Add document. The original PDF bytes remain immutable in PostgreSQL, with their own SHA-256. PDFs are limited to 50 MB, 300 physical pages, 8 MB extracted text in total and 256 KB per page; extracted lines must fit the existing 1800-character passage limit. Encrypted and malformed PDFs are rejected. Image-only pages with detectable raster content are processed by local OCR; PDFs with no readable text after extraction/OCR are rejected. Mixed documents preserve physical page numbering and report pages without text. Blank pages are not indexed. Tables as structured data, handwriting, diagrams and visual interpretation remain separate work.

Extraction uses pinned `pypdf==6.19.0`, plain text mode, in a separate process with a 600-second document wall limit, 240-second CPU limit and 1 GB Linux address-space limit. PDF actions and embedded scripts are not executed. Source downloads use attachment disposition and `nosniff`. View extracted pages verifies the original bytes and the immutable extraction hash, and shows stored plain text, never active PDF content. The [pypdf extraction guide](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md) explains why reading order and table layout may differ from the visible page. Review the original before treating extracted text as authoritative.

Apply `infra/postgres/008-pdf-knowledge.sql` after migrations 006 and 007 on existing volumes. The additive migration creates append-only extraction records and adds nullable page numbers to passages; existing text sources and vectors remain intact. Extraction records preserve parser identity, each page text hash, physical page count and a canonical extraction hash. Retrieval and completed-answer citation verification re-extract the cited physical pages using their recorded parser version and reject changed extraction text, incorrect page ranges or source hashes.

PDF passages never cross pages. Assistant citation cards and TXT exports show page numbers; JSON records include the literal excerpt, physical page number, parser identity, page text hash, source hash and passage hash. These citations identify authenticated text extraction, not proof that every generated claim follows from it. Index new PDF passages using Index documents to enable semantic retrieval.

## Larger documents and OCR

Pages with fewer than 80 embedded text characters and a raster image of at least 128 x 128 pixels use local Tesseract OCR. Pages with an adequate existing text layer use that layer; image text on otherwise text-rich pages is not separately extracted. Blank pages without raster content stay blank. This is printed-text OCR in English and Spanish, not handwriting or diagram interpretation. The upload status explains that scans may take several minutes. Each original page is rendered locally with Poppler, bounded to a 2400-pixel maximum dimension, then recognized with `eng+spa`, LSTM engine and automatic page segmentation. Rendering and recognition each have a 25-second per-page limit. No page is sent to an external service.

The API image pins Tesseract `5.5.0-1+b1`, Poppler `25.03.0-5+deb13u4` and English/Spanish trained-data packages `1:4.1.0-2`. OCR extraction records include executable and trained-data SHA-256 fingerprints, recognition settings, per-page method and text hashes. Citation cards, extracted-page previews and TXT exports label OCR text; JSON includes the page method and parser. Reverification processes only cited pages and caches verified pages within one request, rather than rerunning a whole large scan for each passage. Existing v1 text-PDF records continue to use the original parser and output format; no originals, passages or vectors are rewritten. No additional database migration is required beyond 008.

OCR can confuse digits, units, symbols and reading order. Compare recognized values with the original PDF before using them in an engineering decision. Current tests recognize a scanned copy of the project thermal guide, verify physical page 2, reject an altered OCR-method citation, import a scanned PDF exceeding the previous 5 MB limit and accept 60-page text PDFs. These are implementation checks, not an OCR accuracy benchmark for arbitrary scans. Entire-document extraction rejects files that exceed time/text limits rather than silently storing partial pages.

## Import progress and cancellation

Website uploads start a background import and show page count, completed pages, and whether the current page is reading embedded text or running OCR. Cancel import stops the extraction process group, including Poppler/Tesseract children, and removes temporary files. No document, extraction record or passages are inserted until extraction and chunk preparation finish. Cancellation is accepted before saving starts; during the atomic database registration the button is disabled. Failed registration rolls back the complete document transaction. Closing the dialog leaves an import running. Reloading the website resumes progress for the current session.

Only one background import runs at a time. Up to 20 recent status records are held in API memory for one hour; originals live only in memory/temporary extraction storage until registration. API restarts interrupt active extraction and discard these status records. The website reports a missing import and asks the user to check the library before retrying, since registration may have finished just before restart. Completed documents remain in PostgreSQL. Status records do not contain source bytes or extracted passages. Existing synchronous ingestion remains available for integration clients; the website uses the cancellable background endpoints.

## Search preview

Open Local documents and enter a Search question to inspect up to four matching passages without selecting a study. Search uses the same bounded retrieval and source verification as the study assistant. Results show physical PDF pages or text line ranges, OCR labels, literal passages, original download links and SHA-256 fingerprints. The status identifies hybrid semantic/keyword search or the keyword fallback reason. Search does not generate an AI answer or change the study. Citation IDs are scoped to that search and may change with a different question. Relevance and OCR values still require review.

## Archive and restore

Use Archive beside a document and confirm its name. It leaves the default list, new keyword and semantic searches, indexing batches and active index coverage. Show archived documents reveals retained sources and their Restore controls. Restoring immediately reuses existing embeddings. Originals, extracted pages and passages stay immutable; previous AI citations and original downloads remain verifiable. Reimporting identical bytes deduplicates to the retained source and does not silently restore it.

Existing databases require additive migration `infra/postgres/009-document-visibility.sql` after 008. Fresh databases initialize it automatically. Archive/restore adds ordered append-only visibility events; the application cannot update/delete those events, and database triggers also reject changes by the administrator. Concurrent changes are serialized per document. The local website sends the document UUID and original SHA-256; a changed identity or missing archive confirmation is rejected. Search results already displayed are cleared after a visibility change in this window; search again to refresh other windows. Historical answers remain attached to their original evidence.

## Use a searched question in the study assistant

After a search with verified matching passages, choose Use question in study. A verified structural or thermal study must already be selected. The searched question is copied into its question field and Include local document references is enabled. The dialog closes and the question receives focus. Review it and press Ask local AI to request a new explanation; the transfer itself does not call the model. Running explanations and incomplete/unverified study selections block the transfer. Editing the search question or changing document visibility requires a fresh search before transferring it.

The assistant retrieves and verifies current passages again when asked; preview citation IDs are scoped to the preview and are not carried into the new answer. Archive/index changes can change the next retrieval. Question handoff does not alter solver inputs or approve engineering acceptance.

## OCR language selection

Choose PDF OCR language before importing a new PDF: English, Spanish, or English + Spanish (default). Only the installed local language models are offered. The choice is validated by the API and passed directly as a bounded Tesseract language value; it is not a shell command. The import job, saved extraction settings and PDF citation metadata record the selected language. Extracted-page previews identify it. Citation verification reuses the saved language, independent of the current website selector. Existing v1 text-PDF and v2 combined-language extractions continue to verify with their original parser identities.

An identical byte-for-byte PDF deduplicates to its existing source. Reimporting it with a different selection keeps the original extraction, passages, vectors and language, and the completion message says so. Reprocessing an existing immutable source into a separate extraction version remains future work. Language selection applies to scanned pages; embedded PDF text and plain text/Markdown imports are unchanged.

Failed or cancelled imports show **Retry import** while the page retains the selected file. Retry starts a new import with the exact same file and OCR language; it does not resume partial OCR or reuse partial text. Only one import runs at a time. Reloading the website releases the file from browser memory, so select the original file and language again after a failed or cancelled import recovered from session status. Completed documents still deduplicate by original bytes.

PDF citations in document search and study assistant answers include **Open PDF at page N**, opening the original, hash-checked PDF in a new tab at its physical page number. Printed page labels can differ. Original-source downloads remain available. Page navigation uses the browser PDF viewer; if a viewer ignores the page hint, enter the cited physical page manually.

**View extracted pages** includes a page-by-page text review with previous/next navigation and original PDF page links. It shows the saved extraction method and OCR language, trimmed character count, numeric token count, and Unicode replacement-character count. Empty pages, text shorter than 80 characters, and replacement characters trigger transparent text warnings. Short pages can be legitimate. All OCR text needs manual comparison; an absence of warnings is not evidence of accuracy. These checks use verified extracted text without changing stored documents, passages or citations. No confidence score or review approval is inferred or saved.

The document library supports case-insensitive filename filtering, PDF/Markdown/text type filters, and newest/oldest/name/largest sorting. These local controls combine with **Show archived documents** and survive library refreshes while the page is open. **Reset filters** clears filename/type and restores newest-first sorting. Counts and empty results are shown separately from import status. Filters apply to the API’s loaded list of up to 100 most recent documents; passage search still searches all active documents independently.

**Search in** scopes passage search to one active document or all active documents. The scope is applied in both keyword and semantic SQL queries before ranking limits; an empty result never falls back to other documents. The selector lists active sources in the loaded library (up to 100). Archived sources are excluded. Page citations and literal source checks remain unchanged. Changing scope clears the old preview. **Use question in study** is offered only for all-document searches, because the assistant currently performs its own retrieval across all active references.
